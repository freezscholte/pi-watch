# U2-W3 launch skeleton

This slice runs one reserved command through a detached runner and a detached guardian. The launcher owns only reservation identity and passes the one-time runner capability through stdin; the runner claims and decides launch through the store; the guardian is the only actor allowed to spawn `/bin/sh`.

The guardian uses a private Node IPC channel for hello/readiness, topology, one-time grant, shell outcome and cleanup receipts. It probes its own process group and the runner's group with fixed-argument `ps`, refusing to launch if the topology is not independently verified. A grant is accepted only in the `ready` state. The command receives no runner token or pi-watch internal environment variables.

W3 drains stdout and stderr and discards their bytes. Durable evidence records both streams as unavailable/incomplete. A launched shell records its exit code or signal. Guardian cleanup is best effort: the runner only disconnects the guardian channel and never signals the guardian; the guardian then attempts own-group TERM once, followed by a five-second monotonic grace and own-group KILL intent. Cleanup remains `unconfirmed`; this does not claim descendant death.

Callers must run `preflightLauncher({ dbPath, trustedRoot, runnerEntry? })` before reservation; `launchRunner` repeats the same checks as defense in depth. Before-start cancellation and deadline suppression are decided durably before the grant. Decision errors, lost acknowledgements and runner loss fail closed; no recovered state grants a shell. The runner has a finite seven-second observation budget after a cleanup trigger. Output retention, cancellation polling, heartbeats, stale-witness reconciliation and Pi integration are later slices.

Internal test seams are environment-gated and are not production argv/API, and are centralized in `src/test-seams.ts`: utility path overrides, guardian path overrides, runner pause points, a controller post-launch pause, decision-call failure and committed-response-loss injection, a runner publication delay, a pre-grant IPC disconnect used to exercise the grant-send callback error path, runner/guardian PID and monotonic event logs, and guardian `withhold-spawn`, `withhold-exit`, `withhold-deadline`, `late-topology`, `delay-disconnect`, `disconnect-before-shell`, `disconnect-after-spawn`, and `disconnect-and-hold` modes. The runner explicitly allowlists only the guardian fixture mode/log variables across its environment boundary; all other `PI_WATCH_*` variables are removed before guardian and shell execution. Diagnostics from runner/guardian failures do not include command text, capability tokens or private paths. The topology probe has its own hard timeout: it SIGKILLs only its exact owned child, destroys that child’s stdio, and guardian shutdown stops any live probe.
